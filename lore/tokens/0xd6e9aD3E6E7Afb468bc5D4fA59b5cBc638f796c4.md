## IndexMinter vs. PersonalMinter Structural Architecture

`BODYGUARD` is deployed through the foundational **IndexMinter** ([`solidity/indexminter.sol`](file:///home/mariarahel/src/tsfi2/atropa_pulsechain/solidity/indexminter.sol)), which implements distinct institutional mechanics compared to **PersonalMinter** ([`solidity/personalminter.sol`](file:///home/mariarahel/src/tsfi2/atropa_pulsechain/solidity/personalminter.sol)):

```
+------------------------------------+------------------------------------+
| PersonalMinter (solidity/personalminter.sol) | IndexMinter (solidity/indexminter.sol)    |
+------------------------------------+------------------------------------+
| Divisor: Dynamic per-token `Mint`  | Divisor: Fixed `1,111,111,111 * 10^18` |
| Claim: Single-contract burn only   | Claim: Multi-contract shared basket|
| Debenture: None                    | Debenture: Strict boolean latch    |
```

## Detailed IndexMinter Contract Mechanics

### 1. Global Macro Base Divisor Multiplier

In [`IndexMinter.TT.Multiplier`](file:///home/mariarahel/src/tsfi2/atropa_pulsechain/solidity/indexminter.sol#L87-L89), the mint multiplier uses a system-wide denominator of `1,111,111,111` ether:

$$\text{Multiplier}(\text{addition}) = \left( \frac{\text{addition} + \text{totalSupply}()}{1{,}111{,}111{,}111 \times 10^{18}} \right) + 1$$

* **Low Issuance Predictability**: Because the divisor is a fixed macro constant, small-scale mint additions on tokens like `BODYGUARD` (`228.0` total supply) keep the multiplier at `1` until macro supply scales into hundred-million thresholds, establishing steady initial capital ratios.

### 2. Debenture Latch & Withdrawal Circuit Breaker

IndexMinter introduces an immutable debenture status variable (`bool public Debenture`):

```solidity
function withdraw(address token, uint256 value) public {
    address Owner = IndexMinter.TreasuryTokens(address(this));
    address TokenOwner = IndexMinter.TreasuryTokens(token);
    if(token == address(Parent) || Owner != msg.sender || TokenOwner != msg.sender) revert FuckOff(msg.sender);       
    ERC20(token).transfer(msg.sender, value);
    Debenture = false;
}
```

* **Dual-Registry Ownership Check**: Withdrawing any non-parent asset requires the caller to own both the hosting contract and the asset contract in `IndexMinter.TreasuryTokens`.
* **Permanent Debenture Voiding**: Any withdrawal irreversibly flips `Debenture = false`.
* **Redemption Prohibition**: Once voided, all future calls to [`Claim`](file:///home/mariarahel/src/tsfi2/atropa_pulsechain/solidity/indexminter.sol#L111-L124) revert automatically via `if(!Debenture) revert FuckOff(msg.sender);`.

### 3. Sibling Basket Cross-Contract Claims

The IndexMinter [`Claim`](file:///home/mariarahel/src/tsfi2/atropa_pulsechain/solidity/indexminter.sol#L111-L124) function operates across the entire sibling index basket:

```solidity
function Claim(address Contract, uint256 Amount) public {
    if(!Debenture) revert FuckOff(msg.sender);
    if(address(Parent) == TreasuryBillContract) revert FuckOff(msg.sender);
    address Owner = IndexMinter.TreasuryTokens(Contract);
    if(Owner == address(0x0)) revert FuckOff(msg.sender);
    if(Creator != TTI(Contract).Creator()) revert FuckOff(msg.sender);
    if(address(Parent) != address(TTI(Contract).Parent())) revert FuckOff(msg.sender);
    ERC20 BuyToken = ERC20(Contract);
    bool success1 = BuyToken.transferFrom(msg.sender, address(this), Amount);
    require(success1, string.concat(unicode"Need Approved ", BuyToken.name()));
    if(Contract == address(this)) ERC20Burnable(Contract).burn(Amount);
    Parent.transfer(msg.sender, Amount);
    emit Recovery(msg.sender, Contract, Amount);
}
```

* **Index Basket Fungibility**: If another token contract was created by the same `Creator` and shares the same `Parent` ([`dynamic_0x84d317737611feb25ec3207fba5945f3cb44c143`](https://scan.pulsechain.com/address/0x84d317737611feB25Ec3207fBa5945f3cb44C143) `IPO ㋨`), a participant can submit sibling tokens to `BODYGUARD` to redeem underlying `IPO ㋨` collateral.
* **Absorption vs. Burning**: While `BODYGUARD` burns its own tokens upon claim (`Contract == address(this)`), sibling tokens deposited are absorbed into `BODYGUARD`'s vault, forming an aggregated index portfolio.

### 4. Upstream Hierarchy Resolution

In [`IndexMinter.GetTreasuryTokenOwner`](file:///home/mariarahel/src/tsfi2/atropa_pulsechain/solidity/indexminter.sol#L35-L38), unresolved tokens fall back directly to the `FederalMinter` registry ([`dynamic_0xc15c5f699daf5e1135732139f05d2c05b3ef4354`](https://scan.pulsechain.com/address/0xc15c5F699Daf5e1135732139f05D2c05b3EF4354)), completing the institutional resolution ladder:
